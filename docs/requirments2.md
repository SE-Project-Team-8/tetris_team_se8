# 2차 요구사항 정리 (Requirements 2)

> 원본: Software Engineering Team Project — Requirements 2 (SeoulTech)
> 본 문서는 2차 요구사항 PDF를 팀 작업용으로 정리한 것이다.
> 핵심: **아이템 모드 추가** + **일반 모드 일부 수정(난이도, 줄 삭제 애니메이션)**.
> 1차 요구사항(`docs/requirments1.md`)은 그대로 유효하며, 2차는 그 위에 추가·변경된다.

---

## 1. 개요

- 일반 모드에 **난이도(easy / normal / hard)** 와 **줄 삭제 애니메이션**을 추가한다.
- 시작 메뉴에서 선택할 수 있는 **아이템 모드**를 새로 추가한다.
- 직접 제시되지 않았더라도, 위 기능을 제대로 구현하려면 함께 고쳐야 하는 부분은 팀이 직접 찾아 처리한다.
- 비기능 요구사항도 충분히 만족하도록 구현하고 테스트한다.
- 명확히 언급되지 않은 부분(화면 구성, UI, 추가 게임 정보 표시 등)은 요구사항에 어긋나지 않는 한 자유롭게 구현한다.

## 2. 일반 모드 변경사항

### 2.1 난이도 설정
- [ ] 설정 화면에서 **easy / normal / hard** 3가지 난이도 선택.
- [ ] **I형 블럭(OOOO) 등장 빈도**
  - easy: **20% 더 자주** 등장 (다른 블럭 가중치 10 → I형 12)
  - normal: 동일 확률 (모두 10)
  - hard: **20% 덜** 등장 (I형 8)
- [ ] **줄 삭제에 따른 낙하 속도 증가량**
  - easy: **20% 덜** 증가
  - hard: **20% 더** 증가
- [ ] 난이도별 추가 규칙·점수 부여 방식은 자유 결정 (→ 6. 팀 결정 필요 항목).
- [ ] **스코어보드에서 어떤 난이도의 점수인지 구분**해서 볼 수 있어야 함.
- [ ] (암시) 난이도 설정도 다른 설정처럼 **저장되어 다음 실행 시 유지**.

### 2.2 줄 삭제 애니메이션
- [ ] 삭제되는 줄을 쉽게 알아볼 수 있도록 **삭제 애니메이션** 추가.
  - 예: 삭제될 줄이 하얀색으로 한 번 반짝인 뒤 삭제.

## 3. 확률 기반 블럭 생성

### 3.1 구현
- [ ] 블럭마다 **생성 확률(가중치)을 다르게** 처리.
- [ ] 구현 방법: **Roulette Wheel Selection** (권장).
  - Wikipedia: https://en.wikipedia.org/wiki/Fitness_proportionate_selection
  - 논문: Lipowski, A., Lipowska, D. *Roulette-wheel selection via stochastic acceptance*. Physica A, 2012 (e-class에 `rws.pdf`로 업로드됨)

### 3.2 확률 검증 테스트 (필수)
- [ ] **최소 1,000회 이상** 선택을 반복하는 단위 테스트.
- [ ] 각 블럭이 설정된 확률의 **±5% 오차 범위 이내**로 선택되는지 검증.
- [ ] **실제 게임에서 블럭을 생성하는 코드**가 이 테스트를 통과해야 함 (테스트용 별도 구현 불가).
- 예시: 블럭 4종 중 B의 가중치가 나머지의 2배 → B 40%, 나머지 각 20%.
  1,000회 반복 시 B ≈ 400회, 나머지 ≈ 200회.
- 코드에 문제가 없는데도 오차가 크면 반복 횟수를 늘린다.

## 4. 아이템 모드

### 4.1 시작 메뉴 / 스코어보드
- [ ] 시작 메뉴에 기존 게임 시작에 더해 **"아이템 모드 시작" 메뉴 추가**.
- [ ] 선택한 모드에 따라 게임 형태가 달라짐.
- [ ] 스코어보드에서 **일반 모드와 아이템 모드의 점수를 구분**해서 표시.

### 4.2 아이템 등장 규칙
- [ ] **줄 10개를 삭제할 때마다** 아이템 등장.
- [ ] 10줄이 삭제되면, 그 다음에 **다음 블럭 영역에 새로 나타나는 블럭은 반드시 아이템이거나 아이템을 포함**해야 함.
- [ ] 아이템 형태는 두 가지가 있음.
  - 블럭의 **일부 칸에 아이템이 포함**되는 형태 (예: 줄 삭제 `L`)
  - **블럭 자체가 아이템**인 형태 (예: 무게추)
- [ ] 아이템은 특징적인 모양이나 **기본 블럭과 다른 문자**로 표현.
- [ ] **아이템마다 서로 다른 문자**를 사용해야 함.
- [ ] 제시된 2개 아이템 외에 **팀 자체 아이템 최소 3개 이상** 추가. (→ 4.5)

### 4.3 줄 삭제 아이템 (`L`) — 필수
- [ ] 기본 블럭 안에 포함되며, 문자 **`L`** 로 표시.
- [ ] 블럭이 더 이상 움직이지 못하게 되면(바닥이나 다른 블럭에 닿으면), `L`이 있는 줄을 **꽉 차 있지 않아도 삭제**.
- [ ] `L`이 블럭의 어느 칸에 붙을지는 **무작위**로 결정.
  - 예: I형 블럭은 `OOOL`, `OOLO`, `OLOO`, `LOOO` 중 하나가 무작위로 결정.
- [ ] 아이템으로 삭제된 줄도 **기존 방식대로 점수 계산**.

### 4.4 무게추 아이템 — 필수
- [ ] **너비 4칸**짜리 아이템 (너비만 4칸이면 형태·문자는 자유). 예:
  ```
   OO
  OOOO
  ```
- [ ] 떨어지면서 **아래에 있는 모든 블럭을 지움**.
- [ ] 처음에는 자유롭게 좌우 이동 가능.
- [ ] **바닥이나 다른 블럭에 한 번 닿으면 더 이상 좌우 이동 불가**.
- [ ] 기본적으로 사용이나 지워진 블럭에 대한 **점수 없음**. 원하면 적절한 규칙으로 점수를 줄 수 있음.

### 4.5 팀 자체 아이템 (최소 3개) — 미정
| # | 이름 | 표시 문자 | 형태 (포함형 / 블럭형) | 효과 | 점수 규칙 |
| --- | --- | --- | --- | --- | --- |
| 1 | | | | | |
| 2 | | | | | |
| 3 | | | | | |

- [ ] 팀이 설계한 아이템은 **요구사항·명세서(형태, 기능)를 직접 작성**해야 함.
- [ ] 이 명세는 **평가하는 팀이 구현을 확인할 수 있도록 제공**해야 함 (별도 문서로 정리 예정).

### 4.6 설계 관련
- [ ] **아이템을 쉽게 추가할 수 있는 구조**로 설계 (평가 항목).
- [ ] 명시되지 않은 게임 규칙은 1차 요구사항과 어긋나지 않게 설계. 예:
  - 아이템 표시 + **색맹 모드** 호환
  - **난이도 설정 저장**
  - 게임 실행 환경 (1차 비기능 요구사항 유지)

## 5. 프로젝트 관리 (추가·강화)

- [ ] 진척 상황과 할 일(Task) 배정 내역을 **Trello 등의 도구**로 관리. **← 신규**
  - 할 일과 배정 내역을 근거로 **팀원별 생산성**을 확인할 수 있어야 함.
- [ ] 코드와 필요한 자료(resource)는 Git/GitHub 저장소로 버전 관리.
  - **Branch 관리 정책, Pull Request 처리 정책** 명시.
- [ ] 진행 중 생긴 이슈는 GitHub Issue로 등록하고, **해결 내역을 추적**할 수 있게 관리.

## 6. 평가 관련 주의사항

- 문서는 대략적인 요구사항이다. 세부사항은 팀이 분석해서 결정한다.
- 모호하거나 팀 단독으로 결정하기 위험한 부분은 **e-class 문의로 확정**한다.
- 기능 요구사항과 비기능 요구사항이 섞여서 제시될 수 있다.
- **명시되지 않았지만 암시적으로 요구되는 사항도 평가 대상**이다.
- **Line Coverage: 중간평가 50%, 기말평가 70%** 충족.

## 7. 기존 코드 영향 범위 (참고)

| 영역 | 현재 | 2차 대응 |
| --- | --- | --- |
| 블럭 생성 | `block.UniformTetrominoGenerator` (균등 확률) | 가중치 기반(RWS) 생성기 추가 + ±5% 분포 테스트 |
| 설정 | `settings` 패키지 | `Difficulty` 항목 추가, 저장/로드에 포함 |
| 낙하 속도 | 줄 삭제 시 속도 증가 | 난이도별 증가율 배수 (0.8 / 1.0 / 1.2) |
| 스코어보드 | 이름·점수 | **모드(일반/아이템) + 난이도** 필드 추가, 구분 표시 |
| 시작 메뉴 | 게임 시작 / 설정 / 스코어보드 / 종료 | "아이템 모드" 항목 추가 |
| 보드 셀 | 블럭 색상 | 아이템 종류 정보(문자) 표시 필요, 색맹 모드 호환 |
| 줄 삭제 | 즉시 삭제 | 애니메이션 단계 추가 (삭제 대상 표시 → 삭제) |
