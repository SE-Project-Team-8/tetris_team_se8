# 로컬 대전 테스트 계획

근거: LB-N03(단위 테스트, 기말 Line Coverage 70%), `requirements-analysis.md` 6절 추적표.

> 구현 전 계획이다. 테스트 클래스 이름은 구현하면서 정해지는 대로 고친다.

## 1. 방침

- 규칙(공격·대기열·삽입·승패)은 화면 없이 단위 테스트한다. 로직 PR에 테스트를 함께 올린다.
- 엔진의 시간은 기존 방식대로 `GameEngine.DropTimer`를 가짜로 넣어 테스트에서 직접 넘긴다(`GameEngineTest`의 방식).
- 블럭 순서는 `TetrominoGenerator`를 고정해 재현한다(`BlockBoardDriverTest`의 방식).
- 엔진은 EDT에서만 동작하므로 기존 테스트의 EDT 실행 도우미를 그대로 쓴다.
- **기존 테스트는 한 줄도 고치지 않고 통과해야 한다.** 고쳐야 한다면 1인 모드 동작이 달라졌다는 뜻이다. (LB-I10)
- 현재 `build.gradle`의 통과 기준은 50%다. 기말 기준 70%로 올리는 것은 테스트 담당과 정한다.

## 2. 단위 테스트

### `GarbageQueueTest` — LB-F09~F12
- 빈 대기열에 2줄을 넣으면 2줄, 순서 유지.
- 두 번 넣으면 나중 것이 아래에 붙는다.
- 8줄 + 4줄 → 10줄. 새 공격의 위 2줄만 들어가고 받은 줄 수 2를 돌려준다.
- 10줄인 상태에서 넣으면 변화 없음, 0을 돌려준다.
- 정확히 10줄이 되는 경우(7줄 + 3줄)는 전부 받는다.
- `drain()`은 전부 돌려주고 비운다. 빈 대기열의 `drain()`은 빈 목록.
- `lines()`로 받은 목록을 바꿔도 대기열이 바뀌지 않는다.

### `GarbageLineTest`
- 칸 채움 조회, 범위 밖 열·10칸을 넘는 값 거부, 같은 모양이면 `equals`.

### `BoardGarbageTest` — LB-F07, F08
- 빈 보드에 2줄 삽입: 맨 아래 2줄이 회색, 모양 일치(빈 칸 포함).
- 블럭이 있는 보드에 삽입: 기존 블럭이 줄 수만큼 위로, 종류 유지.
- 삽입한 칸은 `isGarbage`가 true, 기존 칸은 false.
- 위로 넘치지 않으면 false, 맨 위 줄의 블럭이 밀려나면 true.
- 회색 줄이 꽉 차면 일반 줄처럼 삭제되고, 삭제 후 회색 표시가 남은 줄과 어긋나지 않는다.
- `eraseCells`·`clear`가 회색 표시도 지운다.
- 삽입한 회색 칸과 낙하 블럭이 충돌한다(`CollisionChecker`).

### `AttackLinesTest` (`BlockBoardDriver`) — LB-F04, F05
- 1줄 삭제: 공격 줄 없음.
- 2줄·3줄·4줄 삭제: 줄 수만큼, 위에서 아래 순서.
- 모양: 방금 고정한 블럭의 칸만 비어 있다(`rules.md` 2.2의 L자 예시를 그대로).
- 회색 줄을 지워도 공격 줄이 만들어진다(A7).
- 스냅샷에서 회색 칸이 `CellCodes.GARBAGE`로 나온다.

### `VersusEngineTest` (`GameEngine` + `AttackLink`) — LB-F04, F07
- 2줄 이상 삭제하면 `send`가 한 번, 삭제 줄 수만큼의 줄로 불린다. 1줄이면 불리지 않는다.
- 블럭 고정 때마다 `takeIncoming`이 불리고, 받은 줄이 다음 블럭 생성 **전에** 보드에 들어가 있다.
- 블럭이 낙하 중일 때는 대기 중인 줄이 보드에 들어가지 않는다.
- 삽입으로 넘치면 게임 종료(A6).
- 삽입 후 생성 자리가 막혀 있으면 게임 종료.
- `AttackLink.NONE`이면 기존과 같게 동작한다.

### `VersusMatchTest` — LB-F03, F13, F17
- 시작하면 두 엔진이 모두 진행 중이고, 한쪽 조작이 다른 쪽 보드를 바꾸지 않는다.
- P1의 공격이 P2의 대기열에, P2의 공격이 P1의 대기열에 들어간다(반대로 들어가지 않는다).
- 한쪽이 끝나면 상대가 승자이고 상대 엔진도 멈춘다. 결과 알림은 한 번만 온다.
- 일시정지·재개가 두 엔진에 함께 적용된다.
- 중단(`stop`)하면 결과 알림이 오지 않는다.
- 시간제한: 시간이 끝나면 점수가 높은 쪽 승리, 같으면 무승부(A9).
- 시간제한: 일시정지 중에는 남은 시간이 줄지 않는다(A10). 시간 안에 한쪽이 끝나면 그 자리에서 승패가 난다.
- 일반·아이템 방식에서는 시간이 지나도 끝나지 않는다.
- 다시 시작하면 대기열·점수·보드가 초기화된다.

### `VersusItemTest` — LB-F16
- 아이템 방식에서 플레이어별 누적 10줄이 따로 세어진다.
- 줄 삭제 아이템(`L`)이 지운 줄이 삭제 줄 수에 들어가 공격이 된다(A3). 남는 칸이 없는 줄은 빠진다(A4).
- 무게추는 공격을 만들지 않는다.
- 일반·시간제한 방식에서는 아이템이 나오지 않는다.

### `VersusInputTest` — LB-F18, LB-I01
- P1 키는 P1에게, P2 키는 P2에게만 전달된다. 표에 없는 키는 전달되지 않는다.
- 이미 눌린 키의 `KEY_PRESSED`(OS 자동 반복)는 무시된다.
- P1 키를 누르고 있는 중에 P2 키를 눌러도 P1의 반복이 계속된다(반복 타이머를 직접 넘겨 확인).
- 키를 떼면 반복이 멈춘다. 하드드롭은 누르고 있어도 한 번만 실행된다.
- 눌림 상태를 비우면 모든 반복이 멈춘다.
- 오른쪽 `Shift`는 P1 하드드롭이 아니다.

### 화면 테스트 — LB-F01, F02, F14, F15
- `MainMenuScreenTest`: "대전 모드" 항목이 있고 선택하면 방식 선택 화면으로 간다.
- `BattleSelectScreenTest`: `↑` `↓` 이동, `Enter`로 고른 방식이 전달된다, `Esc`로 시작 메뉴.
- `VersusResultScreenTest`: 승자·무승부 문구, 버튼 세 개의 이동 경로. 이름 입력·스코어보드로 가지 않는다.
- 대전 화면: 화면을 이미지로 그려 회색 줄·대기열·남은 시간이 나타나는지 확인한다(기존 `GameScreenTest` 방식. 창을 만들 수 없는 헤드리스 환경에서는 건너뛴다).
