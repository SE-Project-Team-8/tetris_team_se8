# 대전 화면 요구사항 (UI 담당에게 넘기는 문서)

근거: LB-F01, F02, F06, F14, LB-I02~I08. 목업: `docs/design/mockups/BattleSelectScreen.png`, `VersusScreen.png`.

> 이 문서의 화면은 **UI 담당(조상윤·안성현)이 만든다**(`decisions.md` D-12). 로컬 대전 담당은 화면에 필요한 데이터와 동작을 `ui-contract.md`의 연결 지점으로 제공한다.
> 여기에는 요구사항을 지키려면 화면에 **무엇이 보이고 어떻게 넘어가야 하는지**만 적었다. 배치·수치·클래스 이름은 제안이며 UI 담당이 정한다.

## 1. 화면 흐름

```text
시작 메뉴 ─▶ 게임 방식 선택 ─▶ 대전 화면 ─▶ 승자 화면
```

| 어디서 | 조작 | 어디로 |
| --- | --- | --- |
| 시작 메뉴 | "대전 모드" 선택 | 게임 방식 선택 |
| 게임 방식 선택 | `Enter` | 대전 화면 (고른 방식으로 시작) |
| 게임 방식 선택 | `Esc` | 시작 메뉴 |
| 대전 화면 | 승패 결정 | 승자 화면 |
| 대전 화면 | `Esc` → "나가기" 확인 | 시작 메뉴 (승패 없음) |
| 승자 화면 | 다시 대전 | 대전 화면 (같은 방식) |
| 승자 화면 | 방식 선택 | 게임 방식 선택 |
| 승자 화면 | 메인 화면으로 | 시작 메뉴 |

| 화면 | `ScreenRouter` 이름 | 클래스 |
| --- | --- | --- |
| 게임 방식 선택 | `BATTLE_SELECT` | `BattleSelectScreen` |
| 대전 | `VERSUS` | `VersusScreen` |
| 승자 | `VERSUS_RESULT` | `VersusResultScreen` |

## 2. 시작 메뉴와 게임 방식 선택

- `MainMenuScreen`에 **"대전 모드"** 항목을 추가한다. (LB-F01) P2P 항목과의 순서는 `integration.md` 3절.
- 게임 방식 선택 화면은 **일반 대전 / 아이템 대전 / 시간제한 대전** 카드 3개를 세로로 놓는다. (LB-F02)
  - `↑` `↓`로 이동, `Enter`로 시작, `Esc`로 시작 메뉴 복귀. 사용 키를 하단에 안내한다. (LB-I06)
  - 카드마다 한 줄 설명을 둔다. 시간제한 카드에는 제한 시간을 적는다.
  - 카드 아래에 P1·P2 키 셋을 안내한다. 설정에서 바뀔 수 있으므로 현재 설정값을 읽어 표시한다. (LB-I04, `ui-contract.md` 4.3)
  - `Enter`를 누르면 `match.start(고른 방식)`을 호출하고 대전 화면으로 간다.

## 3. 대전 화면

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 대전 모드 — 일반                                             02:31  │
│ ┌────────────┐  P1                             P2  ┌────────────┐   │
│ │            │  NEXT          ┌────┐         NEXT  │            │   │
│ │   P1 보드  │  SCORE         │ VS │        SCORE  │   P2 보드  │   │
│ │   20 × 10  │  LEVEL         └────┘        LEVEL  │   20 × 10  │   │
│ │            │  공격 대기열            공격 대기열 │            │   │
│ └────────────┘                                     └────────────┘   │
│  P1 W A S D · Shift      P 일시정지 · Esc 나가기      P2 ←↑↓→ · Enter │
└─────────────────────────────────────────────────────────────────────┘
```

첫 줄 왼쪽은 게임 방식, 오른쪽은 남은 시간(시간제한 방식만)이다.

- 플레이어마다 **보드, 다음 블럭, 점수, 레벨, 공격 대기열**을 둔다. 보드가 바깥쪽, 정보 패널이 안쪽이다. (LB-I02)
- 보드 테두리는 P1 `UiColors.PLAYER1`, P2 `UiColors.PLAYER2`로 구분한다.
- **공격 대기열 영역**은 10줄×10칸 작은 격자다. 대기 중인 줄을 위에서부터, 빈 칸이 보이는 모양 그대로 회색으로 그린다. 줄 수(`4/10`)를 같이 적는다. (LB-F06)
  - `design-spec.md` §6의 "슬롯 10개 가로 바"는 모양을 보여 주지 못해 요구사항과 맞지 않는다. 목업 `VersusScreen.png`의 격자 표현을 따른다.
- 보드의 회색 줄은 `UiColors.GARBAGE` 바탕에 `> <` 문자로 그린다. 색맹 모드에서도 문자로 구분된다. (LB-F08, LB-I05)
- 시간제한 방식에서만 오른쪽 위에 남은 시간을 `mm:ss`로 표시한다. (LB-I08)
- 줄 삭제 표시, 낙하 예고(고스트), 아이템 문자는 1인 모드와 같게 보여야 한다. `GameScreen`의 셀·보드 그리기를 공용 부품으로 떼어 내 함께 쓰는 방법을 권한다.
- 화면 갱신은 플레이어별 이벤트가 올 때 그 플레이어 영역만 한다. (LB-N01)

### 창 크기

대전 화면에 들어갈 때 창 폭을 넓히고, 나갈 때 설정의 크기로 되돌린다. 높이는 설정값 그대로다. (LB-I05)

| 설정 | 1인 창 | 대전 창 (제안) |
| --- | --- | --- |
| SMALL | 480 × 640 | 1024 × 640 |
| MEDIUM | 540 × 720 | 1152 × 720 |
| LARGE | 600 × 800 | 1280 × 800 |

- 비율은 목업(약 1.6 : 1)을 따랐다. 수치는 구현하면서 칸 크기에 맞춰 조정한다.
- `ScreenRouter.updateWindowSize()`를 그대로 쓴다. 창을 다시 가운데에 놓는다.
- 방식 선택·승자 화면을 넓힌 창에서 보일지, 대전 화면에서만 넓힐지는 전환이 덜 어색한 쪽으로 구현 때 정한다.

## 4. 승자 화면

- 승패가 정해지면 두 보드를 멈춘 상태로 잠시 보여 준 뒤 승자 화면으로 넘어간다.
- 표시: **"P1 승리" / "P2 승리" / "무승부"**, 종료 사유(상대가 더 쌓을 수 없음 / 시간 종료), 두 플레이어의 점수. (LB-F14)
- 버튼: **다시 대전**(같은 방식) / **방식 선택** / **메인 화면으로**. `←` `→`로 이동, `Enter`로 선택. (LB-I07)
- 이름 입력과 스코어보드로 가는 길은 없다. (LB-F15)

## 5. 일시정지와 나가기

- `P`: 두 보드를 함께 멈추고 일시정지 화면을 덮는다. 다시 `P` 또는 "계속하기"로 재개한다. (LB-I03)
- 일시정지 화면의 항목은 1인 모드와 같다: 계속하기 / 메인 화면으로 나가기 / 게임 종료.
  - 현재 `PauseScreen`은 `GameEngine` 하나와 `ScreenRouter.GAME`에 묶여 있다. 대전에서는 `match.pause()`·`resume()`·`stop()`을 부르고 대전 화면으로 돌아가야 한다.
- `Esc`: 두 보드를 멈추고 "메인 화면으로 나갈까요?"를 묻는다. 1인 모드의 확인 대화상자와 같은 문구·기본 선택("계속하기")을 쓴다. 나가면 승패 없이 시작 메뉴로 간다.
- 다른 화면으로 넘어가거나 창이 가려지면 일시정지한다(`GameScreen.onHide`와 같은 동작).

## 6. 확인용 화면

UI 담당의 화면이 들어오기 전에 대전이 도는지 보려고 로컬 대전 담당이 만드는 꾸미지 않은 화면이다. 위 요구사항의 대상이 아니다. `ui-contract.md` 5절을 본다.
