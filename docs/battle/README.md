## 범위

- **포함**: 엔진 2개 동시 구동, 공격과 공격 대기열, 승패 판정, 시간제한, 2인 키 입력 처리, 대전 키 값과 설정 저장,
  `Main`에서의 대전 조립, UI가 화면을 얹을 연결 지점, 확인용 화면 하나, 이 모든 것의 단위 테스트.
- **제외**: 화면 — 시작 메뉴 항목, 방식 선택·대전·승자 화면, 설정 화면의 대전 키 영역, 뿌요풍 비주얼·공격 연출(조상윤·안성현).
  P2P 대전(손동민). 도전 과제.
- 화면을 만들지 않는 것은 `decisions.md` D-12의 결정이며 **UI 담당의 동의가 필요하다.** 연결 지점은 `ui-contract.md`에 적었다.
- 다른 담당과 맞닿는 부분은 `integration.md`에 모았다.

## 작업 순서

로직(1~4)을 먼저 끝내 PR 하나로 올린다. 화면 없이 테스트할 수 있고, UI 담당과 P2P 담당이 이 PR의 연결 지점을 받아 작업을 시작한다.
입력·조립·확인용 화면(5~7)이 두 번째 PR이다. 대전 키는 5번에서부터 설정 값(`VersusKeyBindings`)으로 받게 만들어 기본값으로 먼저 동작시키고, 설정 저장(8)은 그 뒤에 붙인다.

| # | 작업 | 산출물 | 관련 요구사항 |
| --- | --- | --- | --- |
| 1 | 공격 줄과 대기열 | `GarbageLine`, `GarbageQueue` + 테스트 | LB-F09~F12 |
| 2 | 보드·드라이버 | 회색 줄 저장·삽입, 공격 줄 모양 계산 | LB-F05, F07, F08 |
| 3 | 엔진 연결 지점 | 고정 후 공격 전달, 생성 전 대기열 삽입 | LB-F04, F07 |
| 4 | 대전 진행 관리 | `VersusMatch`: 엔진 2개, 승패, 시간제한 | LB-F03, F13, F16, F17 |
| 5 | 2인 입력 | `VersusInput`: 키 분배와 자체 반복 (화면 무관) | LB-F18, LB-I01 |
| 6 | 조립과 확인용 화면 | `Main`의 대전 조립, 실행 인자로 띄우는 확인용 화면 | LB-F03, LB-I01 |
| 7 | 마무리 | 아이템·시간제한 확인, 확인용 화면으로 수동 점검, `ui-contract.md`를 실제 코드에 맞춤 | LB-F16, F17 |
| 8 | 대전 키 저장 | 설정 파일 형식 버전 3, 이전 버전 읽기, 기본값 되돌리기 (설정 화면은 UI 담당) | LB-I11 |
