# 2인 키 입력

근거: LB-F18(창 전체에서 받아 분배), LB-I01(동시 입력에도 즉시·정확 반응), LB-I04(키 안내). 원본 p.7.

> 구현 전 초안이다. `VersusInput`은 계획 중인 클래스 이름이다.

## 1. 키 셋

`docs/design/mockups/BattleSelectScreen.png`의 조작 안내를 따른다. **[제안, A12]**

| 동작 | P1 (왼쪽 보드) | P2 (오른쪽 보드) |
| --- | --- | --- |
| 왼쪽 이동 | `A` | `←` |
| 오른쪽 이동 | `D` | `→` |
| 아래 1칸 | `S` | `↓` |
| 시계방향 회전 | `W` | `↑` |
| 하드드롭 | 왼쪽 `Shift` | `Enter` |
| 일시정지·재개 (공용) | `P` | `P` |
| 나가기 (공용) | `Esc` | `Esc` |

- 대전에서는 설정 화면의 1인용 키(`KeyBindings`)를 쓰지 않는다. 1인용 키를 바꿔도 대전 키는 위 표로 고정이다.
- 키 셋은 게임 방식 선택 화면과 대전 화면 하단에 안내한다. (LB-I04)
- 왼쪽 `Shift`는 `KeyEvent.getKeyLocation()`으로 오른쪽과 구분한다.
- 설정 화면에 P1/P2 키 항목을 넣는 것은 이번 범위에서 뺐다. 넣게 되면 `KeyBindings`를 플레이어별 두 벌로 저장하는 변경이 필요하다.

## 2. 창 전체에서 받아 분배

현재 `GameScreen`은 패널의 `InputMap(WHEN_IN_FOCUSED_WINDOW)`에 `KeyBindings` 한 벌을 묶는다. 대전에서는 다음과 같이 한다.

- `VersusInput`을 `KeyboardFocusManager`의 `KeyEventDispatcher`로 등록한다. 포커스가 어느 컴포넌트에 있든 창의 모든 키 이벤트를 먼저 받는다. `HeldKeys`와 `PauseScreen`이 이미 쓰는 방식이다.
- 대전 화면이 보이는 동안(`onShow`~`onHide`)에만 등록한다. 다른 화면의 입력에는 관여하지 않는다.
- 받은 키를 표에서 찾아 `match.handle(player, action)`으로 넘긴다. 표에 없는 키는 건드리지 않고 통과시킨다.
- 일시정지 중에는 이동 키를 무시하고 `P`(재개)만 처리한다. 확인 대화상자가 떠 있는 동안에도 이동 키를 넘기지 않는다.

## 3. 누르고 있을 때의 반복

**문제.** OS의 자동 반복은 마지막에 누른 키 하나만 반복한다. P1이 `A`를 누르고 있는 중에 P2가 `→`를 누르면 `A`의 반복이 끊겨 P1 블럭이 멈춘다. 1인 모드는 OS 반복에 기대도 되지만 대전은 그럴 수 없다. (LB-I01)

**방법.** OS 반복을 쓰지 않고, 눌림 상태를 직접 추적해 플레이어·키마다 반복시킨다.

- `KEY_PRESSED`: 이미 눌려 있는 키면(OS 자동 반복) 무시한다. 새로 눌린 키면 동작을 한 번 바로 실행하고, 반복되는 동작이면 그 키의 반복 타이머를 시작한다.
- `KEY_RELEASED`: 그 키의 반복 타이머를 멈춘다.
- 반복 타이머는 Swing `Timer`다. 첫 반복까지의 지연과 이후 간격은 상수로 두고 플레이해 보며 맞춘다(시작값: 지연 170ms, 간격 50ms).

| 동작 | 누르고 있을 때 |
| --- | --- |
| 좌우 이동, 아래 1칸, 회전 | 반복 (1인 모드와 같다) |
| 하드드롭, 일시정지, 나가기 | 새로 누를 때 한 번만 (`GameScreen.ONE_PRESS_ACTIONS`와 같다) |

**눌림 상태를 비우는 때.** 창이 포커스를 잃을 때, 일시정지에 들어갈 때, 대전이 끝날 때, 화면을 떠날 때. 떼는 이벤트를 받지 못해 키가 눌린 채로 남는 것을 막는다. (`HeldKeys`가 `activeWindow` 변화에 기록을 비우는 것과 같은 이유다.)

**하드드롭 연타 방지.** 한쪽의 블럭이 고정되어 다음 블럭이 나왔을 때, 누르고 있던 아래 키의 반복은 새 블럭에도 이어진다(1인 모드와 같은 동작). 하드드롭은 한 번만 실행되므로 다음 블럭까지 떨어지지 않는다.

## 4. 알려진 한계

- **키보드 동시 입력 한계.** 일부 키보드는 특정 키 조합 3개 이상을 동시에 인식하지 못한다(고스팅). 소프트웨어로 해결할 수 없다. P1은 왼쪽, P2는 오른쪽 영역으로 키를 나눠 겹침을 줄였다.
- **Linux 개발 환경.** X11에서는 자동 반복이 `KEY_RELEASED`+`KEY_PRESSED` 쌍으로 온다. 이 경우 반복이 OS 속도를 따르지만 동작은 한다. 평가 대상 OS는 Windows 11이므로 반복 간격은 Windows에서 맞춘다.
