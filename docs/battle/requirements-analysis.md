# 로컬 대전 요구사항 분석

근거: `docs/requirments3.md` p.2~7(대전 모드). 표의 "근거" 열에서 `3차 p.4`는 3차 요구사항의 슬라이드 번호, `1차 2.4`·`2차 4.2`는 `docs/requirments1.md`·`requirments2.md`의 절 번호다.

요구사항마다 ID를 붙여 규칙 명세(`rules.md`), 설계(`design.md`), 테스트(`test-plan.md`)에서 가리킨다.
`LB`는 Local Battle, `F`는 명시된 기능, `I`는 암시적 요구, `N`은 비기능 요구다.

## 3. 비기능 요구사항과 제약

| ID | 요구사항 | 근거 |
| --- | --- | --- |
| LB-N01 | 최소 사양(1.2GHz, 1GB)에서 엔진 2개가 동시에 돌아도 플레이에 문제가 없다. 상시 다시 그리기 루프를 두지 않는다 | 1차 3.1, `design-spec.md` §7 |
| LB-N02 | 두 엔진의 자동 낙하 주기가 서로 영향을 주지 않는다 | 1차 2.4, 3.3 |
| LB-N03 | 대전 로직은 단위 테스트로 검증하고, 추가 코드가 기말 Line Coverage 70%를 끌어내리지 않는다 | 3차 p.13 |
| LB-N04 | 대전 규칙은 화면과 분리해, P2P 대전이 같은 규칙 코드를 그대로 쓴다 | 3차 p.2, p.8 |
| LB-N05 | 설계가 맞지 않는 부분은 리팩토링하고, 그 과정이 PR·리뷰로 남는다 | 3차 p.2, p.13 |

제약: Java 21, Swing, 게임 로직은 모두 Swing EDT 한 스레드에서 실행(`GameEngine`의 기존 계약). 창 하나에 보드 두 개를 두는 방식을 택한다(원본 p.7의 두 방식 중).

## 4. 모호한 점과 해석

원문만으로 정해지지 않아 팀이 정해야 하는 항목이다. 상태가 "제안"이면 담당자 해석이고 팀 확인 전이다. 확정되면 상태를 "확정"으로 바꾸고 `rules.md`의 **[제안]** 표시를 지운다.

| # | 모호한 점 | 해석 | 다른 해석 | 상태 |
| --- | --- | --- | --- | --- |
| A1 | LB-F12의 "제일 아래쪽 부분"이 무엇의 아래쪽인가 | **넘어온 줄의 아래쪽**이다. 원문 문장에서 잘라내는 대상과 추가하는 대상이 모두 넘어온 줄이고, 새 줄은 기존 줄 아래에 붙으므로(LB-F10) 합친 결과로 봐도 같다. 기존 줄은 그대로 두고 새 공격의 위쪽 줄부터 빈 자리만큼 받는다 | 기존 대기열의 아래쪽 줄을 버리고 새 공격을 전부 받는다 | 원문으로 확정 (2026-11-23, `decisions.md` D-02) |
| A2 | 대기열의 줄이 보드로 들어가는 양 | 블럭을 하나 고정할 때마다 대기 중인 줄 **전부**가 들어간다 | 한 번에 일부만 들어간다 | 담당자 결정 (2026-11-23, `decisions.md` D-01). 팀 확인 전 |

## 5. 범위와 담당

이 문서의 요구사항은 로컬 대전 전체에 대한 것이다. 로컬 대전 담당은 화면을 만들지 않으므로(`decisions.md` D-12), 요구사항마다 누가 무엇을 하는지 나눈다.

| 요구사항 | 로컬 대전 담당 (로직·연결 지점) | UI 담당 (화면) |
| --- | --- | --- |
| LB-F03~F05, F07, F09~F13, F15~F17, LB-I09, I10, LB-N02~N05 | 전부 | — |
| LB-F18, LB-I01 | 키 분배와 반복 (`VersusInput`) | 창의 키 이벤트를 넘겨줌 |
| LB-F01, F02, LB-I06 | `match.start(방식)` | 시작 메뉴 항목, 방식 선택 화면 |
| LB-F06 | 대기열 줄 목록 알림 | 대기열 영역 그리기 |
| LB-F08, LB-I05 | 회색 칸 코드 (`CellCodes.GARBAGE`) | 회색 칸 그리기, 창 크기, 색맹 모드 |
| LB-F14, LB-I07 | 결과 알림 (승자·사유·점수), 다시 시작 | 승자 화면과 버튼 |
| LB-I02, I08 | 플레이어별 표시 정보, 남은 시간 알림 | 보드·점수·다음 블럭·시간 그리기 |
| LB-I03 | 일시정지·재개·중단 | 일시정지 화면, 나가기 확인 |
| LB-I04 | 현재 대전 키 조회 | 화면에 키 안내 |
| LB-I11 | 대전 키 값과 저장 | 설정 화면의 대전 키 영역 |
| LB-N01 | 값이 바뀔 때만 알림 | 상시 다시 그리기 루프를 두지 않음 |

범위 밖.

- P2P 대전(3차 p.8~11)과 접속 자동화 테스트 — 손동민, 조상윤·안성현.
- 공격 연출(글로우, 회색 뭉치 낙하 등 `design-spec.md` §3.2)과 뿌요풍 비주얼 — 조상윤·안성현.
- 도전 과제(컴퓨터 대전, 채팅, 다인전) — 11/26 이후 결정.
