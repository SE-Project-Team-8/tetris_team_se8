# 무게추(모루) 아이템 명세

근거: `docs/requirments2.md` 4.2, 4.4. 기능 브랜치: `feat/item-5-anvil`.

## 표시와 등장

- 아이템 모드에서 누적 10줄을 삭제할 때마다 아이템 생성 기회를 하나 얻는다.
- 그 뒤 다음 블록 영역에 새로 생성되는 항목은 반드시 아이템이다.
- 현재 구현한 `L`과 무게추를 각각 50% 확률로 선택한다. 아이템 선택 비율은 요구사항에
  지정되지 않아 이 규칙을 사용하며, 생성기는 테스트나 후속 아이템 추가를 위해 교체할 수 있다.
- 일반 모드에서는 아이템을 생성하지 않는다.
- 무게추는 기본 테트로미노와 별개의 블록이며, 너비 4칸 / 높이 2칸 / 점유 6칸이다.
  문자 `W`를 사용해 줄 삭제 아이템의 `L`과 구분한다. 색맹 팔레트에서도 문자를 유지한다.

```text
.WW.
WWWW
```

## 이동과 파괴

1. 위쪽 중앙에서 생성된다. 생성 공간이 이미 점유되어 있으면 기존 블록과 동일하게 게임이 종료된다.
2. 접촉 전에는 빈 공간에서 좌우 이동할 수 있다. 벽이나 점유된 셀을 뚫고 옆으로 이동하지 않는다.
3. 바닥이나 아래의 고정 블록에 한 번이라도 닿으면 좌우 이동이 영구적으로 잠긴다.
   장애물을 지워도 해당 무게추의 잠금은 풀리지 않는다.
4. 한 칸 내려갈 때 새 위치의 점유 셀에 있는 고정 블록을 제거한다. 기존 충돌 때문에 멈추지 않고
   계속 내려가므로, 이동 경로의 너비 4칸 아래에 있는 블록을 바닥까지 제거한다.
5. 즉시 낙하도 같은 하강 처리를 반복하므로 모든 중간 장애물을 제거한다.
6. 무게추 폭 밖의 블록은 유지한다. 셀 파괴는 행 삭제와 달리 위쪽 행을 아래로 압축하지 않는다.

## 문서에서 정하지 않은 세부 규칙

- **회전 없음:** 너비 4칸을 유지한다.
- **바닥 도착 후 소모:** 바닥에 도달한 무게추는 다음 고정 처리에서 사라지고 일반 게임 흐름으로
  다음 블록을 생성한다. 무게추가 바닥에 영구적으로 남는 규칙은 사용하지 않는다.
- **점수 없음:** 자동 낙하, 한 칸 내리기, 즉시 낙하와 개별 셀 파괴 모두 점수를 주지 않는다.
  파괴한 셀을 삭제한 줄 수로 세지 않으며, 이 파괴로 다음 아이템 기회를 얻지도 않는다.
- 일반 블록의 낙하·완성 행 삭제, `L` 아이템의 줄 삭제 점수는 기존 정책을 유지한다.

## 연결 구조

- `block.Anvil`: 불변 좌표와 6칸 형태.
- `Board.eraseCells()`: 요청 전체의 좌표를 먼저 검증한 뒤 셀을 제거한다. 중복 셀은 한 번만 센다.
- `BlockBoardDriver`: 아이템 선택, 낙하, 접촉 잠금, 바닥 도착 후 소모를 처리한다.
- `BoardDriver.awardsDropPoints()`: 무게추에 낙하 점수를 주지 않도록 엔진에 알린다.
  기본값은 `true`여서 기존 보드 드라이버와 일반 블록 점수 정책을 유지한다.
- `AnvilIds.ANVIL_ID = 35`: 보드와 미리보기의 공용 ID. 일반 블록 `0..6`, 포함형 아이템 셀
  (`ItemCellIds`, 보드 `100..`, 미리보기 `1000..`)과 겹치지 않는다.
- `GameScreen`: 실제 형태와 `W` 문자를 보드·미리보기에 표시한다.

## 검증

```powershell
.\gradlew.bat build --no-daemon
```

`AnvilDriverTest`는 실제 10줄 삭제 경로를 통해 무게추를 생성하고 아래 사항을 확인한다.

- 등장 시점, 미리보기 ID, 너비 4칸과 6개 점유 셀
- 접촉 전 좌우 이동 및 벽 경계, 회전 거절
- 최초 접촉 시 잠금, 파괴 이후에도 잠금 유지, 바닥 접촉 시 잠금
- 여러 층의 블록 파괴, 폭 밖의 셀 유지, 행 압축 없음
- 즉시 낙하의 바닥 도달 및 무게추 소모
- 막힌 생성 공간 처리, 새 게임 초기화
- 실제 기본 아이템 선택기에서 L과 무게추 선택
- 엔진에서 자동·한 칸·즉시 낙하 및 파괴에 점수를 주지 않음

`BoardTest`는 개별 셀 삭제의 중복 처리와 잘못된 요청 시 부분 삭제가 발생하지 않는지 확인한다.
기존 `BlockBoardDriverTest`의 L 관련 테스트는 아이템 선택기를 L로 고정해 계속 검증한다.
