# 피버 타임 아이템(`F`) 명세 (팀 아이템 1)

근거: `docs/requirments2.md` 4.2, 4.5, 이슈 #15. 공통 구조는 `README.md`를 본다.

## 표시와 등장

- **포함형** 아이템이다. 10줄 아이템 기회로 선택되면 일반 블록의 무작위 한 칸에 문자 `F`가 붙는다.
  이동·회전 중에도 `F`는 같은 칸을 따라간다.

## 효과

1. `F`가 붙은 블록이 고정되는 순간 피버가 시작된다. `F` 자체는 줄을 지우지 않고 보드를 바꾸지 않는다.
2. 피버는 **10초** 동안 유지되며, 그동안 얻는 **모든 점수가 2배**가 된다.
   (자동 낙하, 소프트 드롭, 하드 드롭, 줄 삭제, 생존 점수 모두 포함)
3. `F` 블록 자신의 낙하·줄 삭제 점수는 고정 전에 계산되므로 2배가 되지 않는다.
4. 피버 중에 `F`를 또 고정하면 남은 시간을 더하지 않고 **10초로 다시 채운다**. 배율도 2배 그대로다(4배가 되지 않음).

## 문서에서 정하지 않은 세부 규칙

- **일시정지:** 일시정지·재개 사이의 시간은 피버 시간에서 빠지지 않는다. 재개하면 남은 초부터 다시 1초씩 줄어든다.
- **게임 종료·새 게임:** 게임을 끝내거나 새로 시작하면 피버도 끝난다.
- **시작 시점:** 피버가 시작되면 1초 생존 타이머를 그 순간에 맞춰 다시 시작한다. 그래서 피버는 정확히 10초다.
  이때 진행 중이던 1초 미만의 생존 시간은 버린다(일시정지 후 재개와 같은 규칙).

## 연결 구조

- `game/item/FeverItem`: `onLock`은 `Set.of()`, `onActivated(effects)`가 `effects.scoreMultiplier(2, 10)`을 요청한다.
  숫자는 `FeverItem.MULTIPLIER`, `FeverItem.SECONDS`.
- `GameEngine`(`GameEffects` 구현): 고정 블록의 점수를 반영한 뒤 `onActivated`를 부르고, `award()`에서 배율을 곱한다.
  남은 초는 기존 생존 타이머의 1초 틱에서 줄어들며, 이 타이머는 실행 중에만 돌기 때문에 일시정지 중에는 멈춘다.
- 등록은 `ItemRegistry.defaults()`에 한 줄이다. 드라이버·화면·`GameEventListener`는 바꾸지 않았다.

## 화면 연동 (UI 담당 요청)

점수 2배 효과는 화면 수정 없이 동작한다. `F` 칸과 미리보기도 `CellCodes`의 문자로 그대로 그려진다.
남은 시간을 보여 주려면 `GameScreen`이 화면을 갱신할 때 `GameEngine.getScoreMultiplierSeconds()`(0이면 숨김)와
`getScoreMultiplier()`를 읽어 `FEVER x2 · 7s`처럼 그린다. 이벤트는 추가하지 않는다.

## 검증

- `FeverItemTest`: 효과 요청과 보드 무변경, `F` 칸 표시와 고정 보고, 10초 동안 2배(생존 점수 포함)와 종료,
  피버 시작 시 1초 틱 재시작, 일시정지 중 시간 정지, 재획득 시 10초로 갱신, 새 게임 시 종료.
- `GameEffectsEngineTest`: 엔진 쪽 배율·카운트다운 규칙. `ItemContractTest`: 문자 고유성과 실제 드라이버 경로.
