# 속도 감소 아이템 명세 (아이템 3)

근거: `docs/requirments2.md` 4.2, 4.5, 이슈 #17. 기능 브랜치: `feat/item-3-slow-down`.
등장 규칙·화면 ID 등 아이템 공통 구조는 `item-structure.md`를 본다.

## 표시와 등장

- 속도 감소는 **포함형** 아이템이다. 10줄 아이템 기회로 선택되면 일반 블록의 무작위 한 칸에 문자 `S`가 붙는다.
  이동·회전 중에도 `S`는 같은 칸을 따라간다.
- 효과는 화면의 `LEVEL` 숫자가 한 단계 내려가는 것으로 드러난다. `GameScreen`이 이미 `engine.getLevel()`을
  그리므로 화면 수정 없이 보인다.

## 효과

1. `S`가 붙은 블록이 고정되는 순간 **현재 속도 단계(레벨)를 1단계 낮춘다**. 다음 블록부터 그 레벨의 낙하 간격으로 떨어진다.
2. 낮춘 단계는 **게임이 끝날 때까지 유지**된다. 이후 블록 수·줄 수가 늘어 레벨이 오를 때도
   아이템이 없었을 때보다 한 단계 낮다. 여러 번 얻으면 그만큼 더 낮아진다.
3. `S` 자체는 줄을 지우지 않고, 점수도 따로 주지 않는다.

## 문서에서 정하지 않은 세부 규칙

- **레벨 1에서 얻으면:** 더 낮출 단계가 없으므로 효과가 없고, 나중을 위해 쌓아 두지도 않는다.
- **최고 레벨에서:** 최고 레벨(10)에서도 정확히 한 단계(9) 내려간다.
- **점수:** 낙하·줄 삭제 점수는 레벨에 비례하므로, 레벨이 내려간 만큼 이후 점수도 함께 줄어든다.
- **새 게임:** 새로 시작하면 이전 게임에서 낮춘 단계는 사라진다.

## 연결 구조

- `game.ItemType.SLOW_DOWN`: 아이템 ID `5`, 문자 `S`, 포함형.
- `GameEngine`: 블록 고정 후 `board.lockedItem()`이 `SLOW_DOWN`이고 현재 레벨이 2 이상이면 낮춘 단계 수를 1 늘린다.
  속도를 계산할 때 `SpeedPolicy.calculate(블록 수, 줄 수, 낮춘 단계 수)`를 호출한다.
- `SpeedPolicy.calculate(int, int, int)`: 기본 메서드. 직접 만든 정책은 기존 2인자 규칙을 그대로 쓴다.
- `DefaultSpeedPolicy`: 기존 방식으로 구한 레벨(최고 레벨로 제한한 값)에서 낮춘 단계 수를 빼고(최소 1),
  그 레벨로 낙하 간격을 계산한다.

## 다른 브랜치와 합칠 때

- 난이도 PR(#38)도 `SpeedPolicy`에 `calculate(int, int, Difficulty)` 기본 메서드를 추가하고
  `GameEngine.updateSpeed()`를 바꾼다. 함께 머지하면 두 값을 모두 받는 메서드 하나로 합쳐야 한다.
  #38의 계산식에서는 블록·줄 기준 단계 수를 각각 최고값으로 제한한 뒤 낮춘 단계 수를 빼면 같은 규칙이 된다.

## 화면 연동 (UI 담당 요청)

속도 감소 효과와 레벨 표시는 화면 수정 없이 동작한다. `S` 칸과 `S` 미리보기는 `item-structure.md`의
"화면 연동"이 반영되어야 화면에 그려진다.

## 검증

```powershell
.\gradlew.bat test --tests "com.team.tetris.game.SlowDownItemTest"
```

`SlowDownItemTest`는 기본 정책의 단계 감소와 최소·최고 레벨, 직접 만든 정책의 기존 규칙 유지,
`S` 칸 표시와 고정 보고, 실제 게임에서 레벨·낙하 간격 감소와 유지, 레벨 1에서 효과 없음, 새 게임 초기화를 확인한다.
