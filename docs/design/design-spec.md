# SE Tetris — 뿌요풍 비주얼 리뉴얼 디자인 스펙 (AI 구현용)

> 이 문서는 UI/UX 구현 담당(또는 담당자의 AI 코딩 어시스턴트)이 그대로 읽고 구현하기 위한 기계 친화 스펙이다.
> 대상 코드: `com.team.tetris.ui.GameScreen`(커스텀 페인팅), `com.team.tetris.block.ColorScheme`.
> 기본 방침: 이미지 에셋 없이 Graphics2D 드로잉 (예외는 폰트 .ttf). 단, §2.1의 렌더링 방식 재량 참고.

- 적용 위치: `ColorScheme`의 standard()/colorBlind() 값 교체.

## 2. 셀 렌더링 공식 (drawBoardCell)

셀 크기를 `c`(px)라 할 때, 모든 수치는 c에서 파생된다. 창 크기 S/M/L 대응은 c 하나만 바꾸면 끝.

| 요소 | 값 | 드로잉 |
| --- | --- | --- |
| 바탕 | 블럭색 | `fillRoundRect(x, y, c, c, r, r)`, `r = round(c * 0.26)` |
| 하단 음영 | 검정 18% | 셀 하단에 높이 `c*0.11`의 어두운 띠 (fillRoundRect, 알파 0.18) |
| 하이라이트 | 흰색 50% | 좌상단 타원 `fillOval(x+c*0.15, y+c*0.12, c*0.26, c*0.17)` |
| 눈 2개 | cellGlyphColor | 지름 `c*0.11` 원 2개, 세로 위치 `y+c*0.30`, 가로 간격 `c*0.22` (중앙 기준 대칭) |
| 입(문자) | cellGlyphColor | IBM Plex Mono Bold, 크기 `c*0.38`, 셀 중앙 하단 `y+c*0.72` 부근에 drawString |
| 표정 생략 | — | `c < 20px`이면 눈 생략, 문자만 |

### 2.1 렌더링 방식 재량 (구현자 판단)

위 공식은 "무엇이 그려져야 하는가"의 스펙이고, **어떻게 그릴지는 구현자가 판단한다**:

- 기본: `paintGame`에서 매 프레임 Graphics2D 직접 드로잉
- **허용**: 컴포넌트(셀 7색×표정, 아이템 아이콘, 모루 등)를 `BufferedImage`로 **미리 렌더해 캐싱**하고 `drawImage`로 찍는 스프라이트 방식 — 매 프레임 fillRoundRect 수십 번보다 저사양에서 오히려 유리할 수 있음. 필요하면 PNG 파일을 resources에 추가하는 것도 가능 (요구사항 위반 아님)
- 어느 방식이든 지켜야 하는 것: ① 캐시는 **셀 크기(S/M/L)·팔레트(일반/색맹) 변경 시 재생성** ② 문자는 여전히 보여야 함(이미지 안에 구워도 됨) ③ 효과(§3)의 1~2프레임 원칙 유지
- 판단 기준: 구현이 단순해지고 1.2GHz/1GB 성능이 확보되는 쪽을 선택

### 셀 상태별 표정

| 상태 | 눈 | 입(문자) | 추가 |
| --- | --- | --- | --- |
| 기본 블럭 | 점 2개 `•_•` | `_` | — |
| 고스트(낙하 예고) | 점 2개 `•_•` | `_` | 바탕 없음, `ghostOutline` 색 2px 점선 테두리 + 문자·눈도 같은 색 |
| 공격줄(garbage) | `>` `<` 문자 | `_` | 바탕 garbage, 글리프 garbageGlyphColor |
| 삭제 플래시 | 없음 | 없음 | cream 단색 채움만 |
| 아이템 칸 | 없음 | 고유 문자 | cream 2px 테두리, §4 참고 |

## 3. 이펙트 (전부 1~2프레임 단발 — 상시 루프 금지)

구현 방식: 이벤트 발생 시각을 필드에 기록 → `paintGame`에서 `now - t < duration`이면 그리기. 기존 아이템 토스트/줄삭제 타이머 경로 재사용.

### 3.1 줄 삭제 "팝"
1. 완성 인식 → 해당 행 셀을 cream 단색으로 (120ms), 눈을 `^ ^`(문자 drawString, 주황 #FFA94F), 입 `_`
2. 행 주변에 별 `✦` 2~3개 drawString (#FFD34E, 행 위·아래 무작위 근처 위치)
3. 행 제거 → 위 블럭 낙하. 낙하 완료 프레임에 착지 눌림(3.3) 재사용
- 여러 줄 동시 삭제 시 모든 행 동시 팝

### 3.2 공격 (대전 모드)
1. **공격 발생**: 공격자 보드 테두리를 플레이어색으로 1회 글로우 펄스 (120ms, 테두리 두께 +3px)
2. **대기열 적재**: 수신자 공격 대기열 새 슬롯을 accent(#FFD34E)로 2회 플래시 후 garbage 색 확정
3. **삽입(핵심 연출)**: 대기열의 줄이 보드에 들어갈 때 — 회색 뭉치 스프라이트(`>_<` 표정, 꼬리 잔상 3개, 알파 0.50→0.12)가 **대기열 쪽에서 출발해 10×20 보드 맨 아래로 떨어지며** 삽입 (~300ms). 삽입 직전 보드 하단 삽입 구역을 accent 점선 + 7% 틴트로 1프레임 하이라이트
- P2P: "attack" 이벤트만 소켓 전송, 이펙트는 양쪽 로컬에서 각자 재생

### 3.3 하드드롭
1. **트레일**: 블럭이 지나온 경로 셀에 잔상 2~3개 (블럭색, 알파 0.50→0.15), 1프레임 후 소멸
2. **착지 눌림**: 착지 프레임에 셀 세로 15% 축소·가로 보정(squash), 눈을 가로선 `-`로 1프레임, 보드 전체 1px 아래로 쉐이크 → 다음 리페인트에 복원

### 3.4 버튼/메뉴 선택(클릭·Enter)
1. **누름** (80ms): 하단 음영 제거 + 버튼 2px 하강 + 배경 8% 어둡게 — "눌린" 질감
2. **확정**: cream 2px 테두리 플래시 + 작은 `✦` 1프레임 → 화면 전환
- 호버/키보드 포커스 이동은 기존 선택 하이라이트(accent 필 + `>` 커서 + scale 1.05) 유지. 마우스·Enter 동일 연출

## 4. 아이템 5종 (ItemRegistry와 문자 일치 — 변경 금지)

| 문자 | 이름 | 형태 | 비주얼 |
| --- | --- | --- | --- |
| `L` | 줄 삭제 | 포함형 | 블럭색 셀 + cream 테두리 2px + `L` 문자 (크기 c*0.45) |
| `B` | 폭탄 | 포함형 | 셀 중앙 검은 구(지름 c*0.53, #241C3B) + 좌상단 하이라이트 + 우상단 도화선(기울어진 선)과 노란 불꽃 점 + 구 안에 작은 `B`(cream). 폭발 시 3×3 범위를 accent 점선 사각형으로 1프레임 표시 |
| `F` | 피버 | 포함형 | 위로 뾰족한 물방울 불꽃(외곽 #D85A30, 안쪽 #FFA94F, 회전 45° 라운드 사각) + 불꽃 중앙에 `F`(#4A1B0C, c*0.31) |
| `S` | 슬로우다운 | 포함형 | 블럭색 셀 + cream 테두리 + `S` 문자 |
| `W` | 무게추 | 블록형 `.WW./WWWW` | 한 덩어리 모루 실루엣: 머리(2칸 폭, 위 라운드) + 받침(4칸 폭, 아래 큰 라운드), steel #4A525E 채움 + cream 2px 외곽선 + 머리 상단 하이라이트 + 받침 내부 연한 세로 구분선 3개(알파 0.16, 4칸 점유 표시) + 받침 중앙 `W`(cream). 낙하 중 **지금 닿은 한 줄만** 연기 퍼프와 함께 분쇄(위 경로는 이미 비어 있음, 아래는 아직 그대로) |

- 포함형(L·B·F·S)은 일반 블럭의 무작위 한 칸에 부착 — 셀 자체는 모체 블럭색 유지.
- B·F·W의 아이콘은 Anvil이 이미 쓰는 커스텀 드로잉 방식(`ANVIL_COLOR` 경로)과 동일하게 셀 위에 그린다. 문자는 항상 함께 그린다(텍스트 기반 요구).

| 용도 | 폰트 | 크기 |
| --- | --- | --- |

## 6. 화면 공통 스타일

- 버튼: 알약형(radius=높이/2). 선택 = accent 채움 + `>` 커서 문자 + 글자 #241C3B. 기본 = panel 채움 + panelBorder 2px. 비활성 = 알파 0.55
- 패널(NEXT/SCORE/LEVEL 등): panel 채움, panelBorder 1px, radius 12. 라벨 10px textMuted 대문자, 수치 Plex Mono Bold cream (LEVEL 수치는 #FFA94F)
- 속도 표기는 항상 **LEVEL 숫자**로 (SPEED/배율 표기 금지 — 코드의 `engine.getLevel()`과 일치, 슬로우다운 효과 가시화). 대전 모드는 P1·P2 각자 LEVEL 패널 표시
- 보드 프레임: board 채움, radius 14~16. 1인 모드 테두리 panelBorder 2px, 대전 P1 player1 / P2 player2 3px
- 공격 대기열: 슬롯 10개 가로 바(높이 7px, radius 4). 찬 슬롯 garbage, 빈 슬롯 흰 7%. 6칸 이상이면 패널 테두리 player2 경고
- 난이도 뱃지: EASY #6FD66F / NORMAL #FFD34E / HARD #D85A30(글자 cream). 스코어보드 행에도 동일 재사용
- 로고: 글자당 블럭색 1개 순환, 라운드 사각 배경 + 하단 음영

## 7. 제약 (절대 위반 금지)

1. **텍스트 기반**: 모든 셀에 문자가 그려진다. 아이콘은 문자를 대체하지 않고 병행한다
2. **색맹 모드**: colorblind 팔레트에서도 모든 구분이 성립해야 한다 (색+문자+표정 삼중 구분)
3. **성능**: 1.2GHz/1GB에서 원활해야 함 — 상시 repaint 루프·배경 애니메이션 금지, 이펙트는 모두 1~2프레임 단발
4. **창 3단계**: S/M/L 모두에서 레이아웃 무결. 셀 크기 하나에서 모든 수치 파생
5. **아이템 문자**: L·B·F·S·W 고정 (ItemRegistry 검증과 일치). 바꾸려면 코드와 명세 동시 수정
