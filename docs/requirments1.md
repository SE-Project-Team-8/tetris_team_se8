# 1차 요구사항 정리 (Requirements 1)

> 원본: Software Engineering Team Project — Requirements 1 (SeoulTech)
> 본 문서는 1차 요구사항 PDF를 팀 작업용으로 정리한 것이다.
> 요구사항은 총 3차에 걸쳐 제시되며, **확장을 염두에 두고 설계**해야 한다.

---

## 1. 프로젝트 개요

- 텍스트 기반 테트리스 게임을 개발한다.
- 1차 목표: 기본 테트리스 게임 구현 (시작 메뉴 → 게임 → 종료 화면).
- 명시된 요구사항을 충족하는 한, 화면 구성 및 세부사항은 팀이 자유롭게 결정 가능.
- 모호한 부분은 팀 임의 결정이 아니라 **e-class에 문의**하여 확정한다.

## 2. 기능적 요구사항 (Functional)

### 2.1 시작 메뉴
- [ ] 실행 시 처음 표시되는 메뉴 화면.
- [ ] 상단에 게임 이름 표시.
- [ ] 메뉴 항목: **게임 시작 / 설정 / 스코어보드 / 게임 종료(프로그램 종료)**.
- [ ] 키보드로 메뉴 간 이동, **엔터(리턴)로 선택**.
  - 다른 키를 쓰는 경우 사용 가능한 키를 화면에 표시.
- [ ] 메뉴가 **차후 추가될 수 있도록 설계** (2·3차 확장 대비).

### 2.2 테트리스 게임 본체
- [ ] 보드: **20줄 × 10칸**.
- [ ] 총 **7가지 테트로미노(블럭)** 가 무작위 등장 — 참조 코드의 7종 모양 구현.
  - 참조: https://github.com/Jindae/SeoulTech-SE-Tetris-Ref
- [ ] 다음 블럭은 **동일한 확률**로 무작위 결정.
- [ ] 각 행이 가득 차면 해당 행 삭제.
- [ ] 각 블럭은 **서로 다른 색상**을 가져야 함.
  - 유사한 모양·좌우 반전 블럭은 **대비되는 색상/무늬**로 구분 용이하게.

### 2.3 화면 구성
- [ ] 보드 + **다음 블럭 표시 영역** + **점수 표시 영역** 포함.
- [ ] 다음 블럭 영역: 블럭이 보드에 생성될 때마다 다음 블럭 갱신 표시.
- [ ] 점수 영역: **실시간으로** 점수 갱신 표시.

### 2.4 게임 조작
- [ ] 블럭은 조작 없이도 **1초에 1칸씩 자동 낙하**.
- [ ] 일정 수 이상 블럭 생성 또는 줄 삭제 시 **낙하 속도 증가**.
- [ ] 키보드 조작:
  - 좌 / 우 / 아래 1칸 이동
  - **시계방향 90도 회전**
  - **하드드롭** (한 번에 바닥까지)
- [ ] **반복 키 입력이 무시되지 않고** 블럭이 즉시·정확하게 반응.
- [ ] 게임 중 **일시정지 / 재개** 키 존재.
- [ ] 진행/일시정지 상태에서 **게임을 종료할 방법** 존재 (alt-F4 등 OS 기능 제외).

### 2.5 점수 계산
- [ ] 블럭이 1칸 떨어질 때마다 점수 획득 (자동/수동 무관).
- [ ] 점수는 실시간으로 화면에 반영.
- [ ] 낙하 속도가 초기보다 빨라진 경우 **추가 점수** 획득.
- [ ] **직접 제시되지 않은 점수 가산/감산 방식 1개 이상 자체 구현** (예: 여러 줄 동시 삭제 보너스 등 — 팀 결정 필요).

### 2.6 색맹 모드
- [ ] 설정에서 색맹 모드 on/off.
- [ ] 적록색맹 및 청황색맹도 블럭 구분이 쉬운 색상으로 전환.
- 참고 자료:
  - 접근성 가이드: https://nuli.navercorp.com/community/article/1132656
  - 유니버설디자인 연구: http://aodr.org/xml/00201/00201.pdf
  - 적록 색각 색변환 기법: https://www.koreascience.or.kr/article/JAKO201310837317613.pdf

### 2.7 설정 화면
- [ ] 게임 화면 크기 조절 — **최소 3가지 이상 미리 정의된 크기**.
- [ ] 게임 조작 키 설정(키 바인딩 변경).
- [ ] 스코어보드 기록 초기화.
- [ ] 색맹 모드 켜기/끄기.
- [ ] **모든 설정을 기본값으로 되돌리기**.
- [ ] 변경된 설정은 저장되어 **다음 실행 시 동일하게 불러와** 적용.
- 그 외 필요한 설정 추가 가능.

### 2.8 게임 종료
- [ ] 더 이상 블럭을 쌓을 수 없으면 게임 종료.
- [ ] 종료 시 스코어보드 표시.
- [ ] 스코어보드 등재 대상 점수인 경우 **이름 입력 화면** 표시.
- [ ] 입력 후 스코어보드를 갱신하고, **방금 등록한 이름·점수를 강조 표시**.
- [ ] 처리 후 시작 메뉴로 복귀 또는 프로그램 종료.

### 2.9 스코어보드
- [ ] 역대 점수 순위를 **높은 순으로 정렬**하여 이름·점수 등 표시.
- [ ] **상위 10개 이상** 기록 보존.
- [ ] 설정에서 초기화하기 전에는 **프로그램을 종료해도 기록 유지** (영속화).
- 그 외 사항은 자유 설계.

## 3. 비기능적 요구사항 (Non-Functional)

### 3.1 실행 환경
- [ ] **Java 21 이상** 설치 환경에서 오류 없이 실행.
- [ ] 대상 OS: **Windows 11** 또는 macOS 26 이상 — *(팀 결정: Windows 11)*.
- [ ] 최소 사양: 1.2GHz 프로세서, 1GB RAM, 500MB 여유 디스크.
- [ ] 위 사양에서 플레이에 문제 없는 성능 제공.

### 3.2 프로젝트 관리
- [ ] 코드는 **VCS(Git)** 로 관리.
- [ ] 이슈 및 해결 상황을 기록·관리 (GitHub Issues).
- [ ] **팀원별 업무 분담 기록·관리** (`docs/roles.md`).
- [ ] 중간·최종 결과물에서 위 사항을 모두 제시 가능해야 함.

### 3.3 테스트
- [ ] 단위 테스트를 충분히 작성 — **Line Coverage 기준 직접 작성한 코드의 50~70% 이상**.
- [ ] **비기능 요구사항 검증 테스트 1개 이상** 존재 (예: 낙하 주기 정확도).
- [ ] 테스트도 코드와 동일하게 VCS로 관리.
- [ ] 변경 발생 시마다 손쉽게 테스트를 실행·검증할 수 있는 체계
      — unit test framework(JUnit 5) + code coverage(JaCoCo) 지속 관리 + CI.

### 3.4 실행 및 배포
- [ ] 배포용 패키지를 손쉽게 만들 수 있는 체계 (jpackage 예정).
- [ ] 패키지에는 **아이콘이 포함된 실행파일** 포함.
- [ ] **더블클릭 등 OS 지원 동작으로 실행** — 추가 명령어 입력·설정 없이 실행 가능해야 함.
  - `java -cp xxx Tetris` 식의 명령 프롬프트 입력 방식은 불가.
- [ ] 대상 OS는 Windows / macOS 중 하나 — *(팀 결정: Windows 11)*.
- [ ] Java 21 이상 설치·경로 설정은 가정 가능. 또는 JRE를 패키지에 포함하는 방식도 가능.

## 4. 주의사항 (평가 관련)

- 문서는 대략적인 요구사항이며, 세부사항은 팀이 분석하여 결정한다.
- 모호하거나 팀 단독 결정이 위험한 부분은 **e-class 문의로 확정**하고, 그 결정 근거를 기록한다.
- 각 요구사항에는 기능/비기능이 섞여 제시될 수 있다.
- **명시되지 않았지만 암시적으로 요구되는 사항도 평가 대상**이다.
- 강의에서 배우는 내용을 프로젝트에 적용할 것.
